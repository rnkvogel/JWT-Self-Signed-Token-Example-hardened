<h1>Millicast Secure Viewer Token Gateway (Node.js)</h1> <p> This project hosts a simple <strong>“View Stream”</strong> page that requests a short-lived <strong>Millicast Subscribe JWT</strong> from a protected server endpoint (<code>/api/token</code>). The <strong>MASTER_TOKEN never leaves the server</strong>. </p> <hr/> <h2>What this protects (and what it doesn’t)</h2> <ul> <li><strong>Stops mirrored/copycat pages</strong> on other domains from minting tokens via browser JS (SameSite cookies + CSRF + Origin checks).</li> <li><strong>Keeps the master token server-side</strong> (no master token in frontend code).</li> <li>Mints <strong>short-lived tokens</strong> (recommended: 60–180 seconds).</li> </ul> <p> <strong>Reality check:</strong> No public website can be made “impossible to proxy” in all cases. But this design prevents “spoofed” frontend copies from calling your token endpoint and receiving a token. </p> <hr/> <h2>Requirements</h2> <h3>Millicast</h3> <ul> <li>You need your <strong>Account ID</strong> and <strong>Stream Name</strong> (example: <code>accountId</code> / <code>streamName</code>).</li> <li>Your playback must be configured to use <strong>Subscribe tokens</strong> (secure playback).</li> </ul> <h3>Server</h3> <ul> <li>Node.js v18+ recommended (you’re on Node v20, which is perfect).</li> <li><strong>HTTPS is required in production</strong> (cookies are <code>secure</code> and won’t work on HTTP).</li> </ul> <hr/> <h2>Project Layout</h2> <pre><code>millicast-token-gateway/ package.json server.js .env public/ index.html app.js (recommended: put JS here to satisfy CSP) </code></pre> <hr/> <h2>Environment Variables</h2> <p>Create a file named <code>.env</code> in the project root (same folder as <code>package.json</code> and <code>server.js</code>).</p> <h3>Example <code>.env</code></h3> <pre><code>MASTER_TOKEN=YOUR_MILLICAST_MASTER_TOKEN ALLOW_ORIGIN=http://localhost:3000 COOKIE_SECRET=put_a_long_random_secret_here PORT=3000 </code></pre> <p> Your current format is correct: <code>KEY=VALUE</code> per line (e.g. <code>ALLOW_ORIGIN=http://localhost:3000</code>). :contentReference[oaicite:1]{index=1} </p> <h3>What each variable means</h3> <ul> <li> <strong>MASTER_TOKEN</strong><br/> The Millicast master token used to sign Subscribe JWTs (HS256 secret).<br/> <em>Never put this in frontend code or commit it to git.</em> </li> <li> <strong>ALLOW_ORIGIN</strong><br/> The only allowed browser origin that can call the token endpoint.<br/> Use <code>http://localhost:3000</code> for local testing, and <code>https://YOURSITE.com</code> in production. </li> <li> <strong>COOKIE_SECRET</strong><br/> A long random secret for signing the session cookie.<br/> Generate one with: <code>openssl rand -hex 32</code> </li> <li> <strong>PORT</strong><br/> Port the Node server listens on locally (default 3000). </li> </ul> <hr/> <h2>Install &amp; Run (Local)</h2> <ol> <li> <strong>Install dependencies</strong> <pre><code>npm install</code></pre> </li> <li> <strong>Install dotenv</strong> (so Node reads the <code>.env</code> file) <pre><code>npm install dotenv</code></pre> </li> <li> <strong>Load dotenv at the top of <code>server.js</code></strong><br/> Add this as the <em>first line</em>: <pre><code>require("dotenv").config();</code></pre> </li> <li> <strong>Start</strong> <pre><code>npm start</code></pre> </li> </ol> <p>Open: <code>http://localhost:3000</code></p> <hr/> <h2>Fixing the CSP “inline script blocked” error</h2> <p> If you see: <code>Executing inline script violates Content Security Policy</code>, that means your page has inline JS but your CSP is <code>script-src 'self'</code>. </p> <p><strong>Recommended fix:</strong> move inline JS into a file.</p> <ol> <li>Create <code>public/app.js</code> and move your JS into it.</li> <li>In <code>public/index.html</code>, remove the inline <code>&lt;script&gt;...&lt;/script&gt;</code> and use: <pre><code>&lt;script src="/app.js"&gt;&lt;/script&gt;</code></pre> </li> </ol> <hr/> <h2>How it works (high level)</h2> <ol> <li>User opens <code>/</code> (your “View Stream” page).</li> <li>The page fetches a CSRF token from <code>/api/csrf</code> (same-origin).</li> <li>The page POSTs to <code>/api/token</code> with CSRF + SameSite session cookie.</li> <li>Server returns <code>{streamId, token}</code>.</li> <li>Browser opens the Millicast hosted viewer: <pre><code>https://viewer.millicast.com/?streamId=ACCOUNT/STREAM&amp;token=JWT</code></pre> </li> </ol> <hr/> <h2>Deployment (Novice-friendly)</h2> <h3>Important: HTTPS required</h3> <ul> <li>This project uses <code>secure: true</code> cookies.</li> <li>That means <strong>production must run on HTTPS</strong> or the session cookie won’t work.</li> </ul> <h3>Typical deployment choices</h3> <ul> <li><strong>VPS + Nginx</strong> (you manage the server)</li> <li><strong>Cloudflare</strong> in front of your origin (recommended for WAF/rate-limit)</li> <li><strong>Render / Railway / Fly.io</strong> (easy hosting; set env vars in dashboard)</li> </ul> <h3>VPS + Nginx (simple approach)</h3> <ol> <li>Run Node app on <code>127.0.0.1:3000</code></li> <li>Use Nginx for HTTPS and reverse proxy</li> </ol> <p>Example Nginx config snippet:</p> <pre><code>server { listen 443 ssl; server_name YOURSITE.com; # TLS cert config here... location / { proxy_pass http://127.0.0.1:3000; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; } } </code></pre> <h3>Setting environment variables in production</h3> <p> Most hosting platforms do <strong>not</strong> use a <code>.env</code> file. Instead, you paste values into the platform UI as “Environment Variables”: </p> <ul> <li><code>MASTER_TOKEN</code></li> <li><code>ALLOW_ORIGIN=https://YOURSITE.com</code></li> <li><code>COOKIE_SECRET</code></li> </ul> <hr/> <h2>Git Safety</h2> <p><strong>Do not commit secrets.</strong></p> <p>Add this to <code>.gitignore</code>:</p> <pre><code>.env</code></pre> <hr/> <h2>Troubleshooting</h2> <ul> <li> <strong>“ERROR: MASTER_TOKEN is not set”</strong><br/> Ensure <code>dotenv</code> is installed and <code>require("dotenv").config()</code> is the first line of <code>server.js</code>. </li> <li> <strong>403 “Forbidden origin”</strong><br/> Your <code>ALLOW_ORIGIN</code> must match the browser origin exactly (scheme + host + port).<br/> Example local: <code>http://localhost:3000</code><br/> Example prod: <code>https://YOURSITE.com</code> </li> <li> <strong>Viewer opens but playback is unauthorized</strong><br/> Confirm your stream requires subscribe authentication and the token is not expired. </li> </ul> <hr/>
